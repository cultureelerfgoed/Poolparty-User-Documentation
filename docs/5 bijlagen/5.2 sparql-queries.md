# SPARQL-voorbeelden voor beginners

Met SPARQL vraag je gegevens uit jouw PoolParty-thesaurus op. Begin met deze voorbeelden. Kopieer steeds de hele query, inclusief de regels met `PREFIX`.

Open het tabblad **SPARQL** van jouw project of gebruik het [SPARQL-endpoint van de CHT](https://data.cultureelerfgoed.nl/PoolParty/sparql/term/id/cht). Een endpoint is het adres waar je queries uitvoert. Je toegang en de beschikbare gegevens kunnen per project verschillen.

## Lees eerst deze regel

```sparql
?concept skos:prefLabel ?prefLabel .
```

Deze regel vraagt: **welke voorkeursnaam heeft dit concept?**

- `?concept` bevat de URI van het concept.
- `skos:prefLabel` is de echte eigenschap voor de voorkeursnaam.
- `?prefLabel` bevat de gevonden voorkeursnaam.
- De punt sluit de regel af.

Een naam met `?` is een variabele: daar vult de query een gevonden waarde in. `?prefLabel` is dus een variabele; `skos:prefLabel` is de eigenschap in jouw gegevens.

## Wat doet PREFIX?

Met `PREFIX skos:` geef je een korte naam aan `http://www.w3.org/2004/02/skos/core#`. Zo schrijf je `skos:prefLabel` in plaats van de volledige URI `http://www.w3.org/2004/02/skos/core#prefLabel`.

We gebruiken ook `PREFIX rdf:` voor `rdf:type`. Met `?concept rdf:type skos:Concept .` selecteer je concepten. Zo krijg je geen begrippenschema’s in je resultaten die ook een voorkeursnaam hebben.

| Eigenschap | Betekenis |
| --- | --- |
| `rdf:type` | Geeft aan van welk type een bron is. |
| `skos:prefLabel` | De voorkeursnaam van een concept. |
| `skos:altLabel` | Een alternatieve naam voor hetzelfde concept. |
| `skos:broader` | Een relatie naar een breder begrip. |

## 1. Concepten met hun voorkeursnaam

Deze query toont twee kolommen: de URI en de voorkeursnaam. Je krijgt namen in alle beschikbare talen.

```sparql
PREFIX skos: <http://www.w3.org/2004/02/skos/core#>
PREFIX rdf: <http://www.w3.org/1999/02/22-rdf-syntax-ns#>

SELECT ?concept ?prefLabel
WHERE {
  ?concept rdf:type skos:Concept .
  ?concept skos:prefLabel ?prefLabel .
}
ORDER BY ?prefLabel
LIMIT 25
```

`SELECT` bepaalt welke kolommen je ziet. In `WHERE` staan de regels waaraan de gegevens moeten voldoen. `ORDER BY` sorteert op naam. `LIMIT 25` toont maximaal 25 rijen, zodat je met een overzichtelijk resultaat begint.

Een concept met labels in meerdere talen kan meerdere rijen opleveren.

## 2. Alleen Nederlandse voorkeursnamen

Voeg een taalfilter toe. `LANG(?prefLabel)` leest de taal van het label. Met `= "nl"` kies je labels met de taalaanduiding Nederlands.

```sparql
PREFIX skos: <http://www.w3.org/2004/02/skos/core#>
PREFIX rdf: <http://www.w3.org/1999/02/22-rdf-syntax-ns#>

SELECT ?concept ?prefLabel
WHERE {
  ?concept rdf:type skos:Concept .
  ?concept skos:prefLabel ?prefLabel .
  FILTER(LANG(?prefLabel) = "nl")
}
ORDER BY ?prefLabel
LIMIT 25
```

In de gegevens ziet zo’n label er bijvoorbeeld uit als `"kerkgebouwen"@nl`. De toevoeging `@nl` is de taalaanduiding; je typt die niet als onderdeel van de naam in PoolParty.

Deze filter selecteert precies de taalcode `nl`. Labels met bijvoorbeeld `en` of zonder taalaanduiding vallen buiten het resultaat.

## 3. Eén Nederlandse naam zoeken

Zoek naar de voorkeursnaam `"kerkgebouwen"@nl`. Vervang **kerkgebouwen** door een naam uit jouw thesaurus. Laat de aanhalingstekens en `@nl` staan.

```sparql
PREFIX skos: <http://www.w3.org/2004/02/skos/core#>
PREFIX rdf: <http://www.w3.org/1999/02/22-rdf-syntax-ns#>

SELECT ?concept ?prefLabel
WHERE {
  ?concept rdf:type skos:Concept .
  ?concept skos:prefLabel ?prefLabel .
  FILTER(?prefLabel = "kerkgebouwen"@nl)
}
LIMIT 25
```

Deze query zoekt een exacte naam, inclusief de taal. Hoofdletters en spelling moeten overeenkomen. Geen resultaat kan dus betekenen dat het concept een andere voorkeursnaam heeft.

## 4. Alternatieve namen met OPTIONAL

Niet elk concept heeft een alternatieve naam. Met `OPTIONAL` vraag je die naam op **als die er is**. Het concept blijft in het resultaat staan als er geen Nederlandse alternatieve naam is.

```sparql
PREFIX skos: <http://www.w3.org/2004/02/skos/core#>
PREFIX rdf: <http://www.w3.org/1999/02/22-rdf-syntax-ns#>

SELECT ?concept ?prefLabel ?altLabel
WHERE {
  ?concept rdf:type skos:Concept .
  ?concept skos:prefLabel ?prefLabel .
  FILTER(LANG(?prefLabel) = "nl")

  OPTIONAL {
    ?concept skos:altLabel ?altLabel .
    FILTER(LANG(?altLabel) = "nl")
  }
}
ORDER BY ?prefLabel ?altLabel
LIMIT 25
```

De taalfilter voor `?altLabel` staat **binnen OPTIONAL**. Daardoor blijft een concept zonder Nederlandse alternatieve naam in beeld. Zet je deze filter buiten het blok, dan vallen die concepten uit het resultaat.

Voorbeeld van de uitkomst, met verzonnen URI’s:

| concept | prefLabel | altLabel |
| --- | --- | --- |
| `https://example.org/concept/1` | `"kerkgebouwen"@nl` | `"kerkgebouw"@nl` |
| `https://example.org/concept/2` | `"gebouwen"@nl` | *(leeg)* |

Heeft een concept meerdere Nederlandse alternatieve namen? Dan krijg je voor elke naam een rij. `LIMIT 25` begrenst het aantal rijen, niet het aantal unieke concepten.

## 5. Het bredere begrip erbij tonen

Met `skos:broader` zoek je het bredere begrip. Daarna vraag je ook de voorkeursnaam van dat begrip op.

```sparql
PREFIX skos: <http://www.w3.org/2004/02/skos/core#>
PREFIX rdf: <http://www.w3.org/1999/02/22-rdf-syntax-ns#>

SELECT ?concept ?prefLabel ?broader ?broaderPrefLabel
WHERE {
  ?concept rdf:type skos:Concept .
  ?concept skos:prefLabel ?prefLabel .
  FILTER(LANG(?prefLabel) = "nl")

  ?concept skos:broader ?broader .
  ?broader skos:prefLabel ?broaderPrefLabel .
  FILTER(LANG(?broaderPrefLabel) = "nl")
}
ORDER BY ?prefLabel
LIMIT 25
```

Bij **kerkgebouwen** kun je bijvoorbeeld **gebouwen** als breder begrip terugkrijgen, als jouw thesaurus die relatie bevat. Deze query toont alleen concepten met een bredere relatie én een Nederlandse voorkeursnaam aan beide kanten. Topconcepten zonder breder begrip verschijnen hier niet.

## 6. Concepten zonder Nederlandse voorkeursnaam

Deze query laat zien welke concepten geen `skos:prefLabel` met taalcode `nl` hebben. Dat helpt je om ontbrekende Nederlandse namen te vinden.

```sparql
PREFIX skos: <http://www.w3.org/2004/02/skos/core#>
PREFIX rdf: <http://www.w3.org/1999/02/22-rdf-syntax-ns#>

SELECT ?concept
WHERE {
  ?concept rdf:type skos:Concept .

  FILTER NOT EXISTS {
    ?concept skos:prefLabel ?prefLabel .
    FILTER(LANG(?prefLabel) = "nl")
  }
}
ORDER BY ?concept
LIMIT 25
```

`FILTER NOT EXISTS` betekent hier: houd het concept alleen over als je **geen Nederlandse voorkeursnaam** vindt. Je krijgt de URI’s van de concepten die je moet bekijken. Ook een concept met alleen een Engels label, of met een Nederlandse alternatieve naam maar zonder Nederlandse voorkeursnaam, verschijnt in deze lijst.

Deze query controleert precies de taalcode `nl`. Een label met `nl-NL` valt buiten die selectie. Spreek binnen jouw project af welke taalcode je gebruikt.

Een treffer is niet automatisch een fout in SKOS. Voor een Nederlandstalige thesaurus kan jouw project wel vereisen dat elk concept een Nederlandse voorkeursnaam heeft.

## Zelf aanpassen

- Verander `LIMIT 25` in `LIMIT 10` voor een kleiner resultaat.
- Verander `"nl"` in `"en"` om Engelse labels te zoeken.
- Verander in voorbeeld 3 de naam en, als je een andere taal kiest, ook `@nl`.

De voorbeelden lezen gegevens. Voor de betekenis van de velden kun je de [begrippenlijst]({% link docs/6. glossary.md %}) raadplegen.

Bron: [W3C: SPARQL 1.1 Query Language](https://www.w3.org/TR/sparql11-query/), met uitleg over taalfilters en optionele waarden.
